# MyEmulator DMA2D DMA 最適化

## 概要
エミュレータ上の `fill_rect` 等のピクセル塗りつぶし処理は、毎ピクセルごとにCPU命令が実行されるため、非常に低速（全画面描画で数百万命令）でした。
これを解決するため、MyEmulatorに**DMA2D DMA (Direct Memory Access)**のハードウェア機能を実装しました。

## 実装内容
1. **I/Oポートのマッピング (MyEmulator)**
   `IO_BASE` (0x2400_0000) 付近にDMA操作用のレジスタを割り当てました。
   - `0x2400_0020`: `DMA2D_DEST_ADDR` (VRAM上の書き込み先アドレス)
   - `0x2400_0024`: `DMA2D_COLOR_ADDR` (塗りつぶす色情報)
   - `0x2400_0028`: `DMA2D_WIDTH_ADDR` (描画幅)
   - `0x2400_002C`: `DMA2D_HEIGHT_ADDR` (描画高さ)
   - `0x2400_0030`: `DMA2D_STRIDE_ADDR` (1行あたりのピクセル幅 / 画面幅)
   - `0x2400_0034`: `DMA2D_CMD_ADDR` (1 を書き込むとDMA転送開始)

2. **高速化の実装 (Rust)**
   エミュレータ側で `DMA2D_CMD_ADDR` への書き込みを検知すると、Rustの `slice::fill` を用いて、VRAM配列(`self.vram`)内の指定領域を一括で上書きします。これにより、ソフトウェアでのループ処理をネイティブのメモリ操作（実質的な `memset`）に置き換えることができ、ほぼ一瞬で描画が完了します。

3. **MyKernelの対応 (`graphics.mln`)**
   MyLangアセンブラ (`myas`) は `movi` 命令の即値として21ビットまでしか扱えないため、0x2400_0000番台のポインタを関数内で直接記述するとビルドエラー（SIGABRT）が発生します。
   そのため、これらのレジスタアドレスは**グローバル変数として定義**し、データセクション経由でロードすることで回避しています。

## 効果
描画にかかるエミュレート命令数が数百万から数十に激減し、User Timeが約1.2秒から0.03秒へと劇的に高速化されました。
