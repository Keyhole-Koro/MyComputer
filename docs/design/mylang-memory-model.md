## 1. 方針

- **メモリ安全。** 安全な（unsafe でない）ソースからは、解放済みのメモリ、範囲外、初期化
  されていないメモリに触れない。触れようとすれば、コンパイルエラーか trap になる。
- **2つの書き方を、1つの仕組みの上で選べる。**
  - **rc モード**（既定）: 参照数で管理するものを、代入で自由に共有できる。
  - **owned モード**: 同じものを所有権（move）と借用で扱い、共有は明示する。
- **モードの違いは規則 M2 の1点だけ。** オブジェクトの表現、借用の規則、ライブラリは共通。
  owned で通るプログラムは、rc でも同じに動く（規則 M3）。
- **構文は今の C 風のまま。** trait もそのまま使う。

所有権で書いたコードは、rc から見ると「参照数がずっと1のままのコード」になる。だから
2つのモードを、別々の言語に分けずに1つの仕組みの上に置ける。

## 2. 用語

| 用語 | 意味 |
| --- | --- |
| 持ち主 | 値を最後に片付ける責任を持つ変数・フィールド・オブジェクト |
| move | 片付ける責任を別の持ち主へ移すこと。元はゼロになる |
| 共有 | 参照数を1増やして、同じものの持ち主を1人増やすこと |
| drop | 持ち主がいなくなった値を片付けること |
| オブジェクト | `new` で作るヒープ上の値。参照数を持つ |
| 共有ポインタ | オブジェクトを指すポインタ `T^`。参照数に数えられ、null にならない（書き方は §13 で検討中） |
| 借用 | 持ち主を変えずに、一時的に値を使わせる参照（`borrow T` / `borrow mut T`） |
| trap | 実行時検査の失敗で、プログラムを止めること（§8） |

## 3. 値の種類

**規則 V1（ゼロ値）** 変数・フィールド・配列の要素は、初期化しなければゼロで始まる。
整数は 0、bool は false、enum は数値 0、`Option` は None、生ポインタは null、struct と
配列は要素ごとにゼロ。共有ポインタ `T^` にはゼロ値がない（規則 O4）。そのため `T^` の
変数・フィールド（と、それを含む struct・配列）は必ず初期化する。無いことがある所は
`Option<T^>` にすれば、ゼロ値は None になる。

**規則 V2（種類）** 値の種類は型から自動で決まる。`impl Copy` のような宣言は要らない。

| 種類 | 型 | 代入・値渡し・return |
| --- | --- | --- |
| データ | 整数、bool、enum、関数値、`Text<N>`、生ポインタ `T*` | コピー |
| 共有できる値 | 共有ポインタ `T^`、`String`、`Vec<T>`、`HashMap<K, V>` | rc では共有、owned では move（規則 M2） |
| 所有する値 | `drop` を持つ struct（今の `FileHandle`、`HeapBlock`、`NewNode` などのガード） | move |
| 借用 | `borrow T`、`borrow mut T`、`str` | 借用の規則（§5） |

struct・配列・enum の種類は、中身のうちいちばん強い種類になる（所有する ＞ 共有できる ＞
データ）。データだけでできた struct はコピーになる。

**規則 V3（コピー）** データは、代入・値渡し・return でビットごとにコピーされる。

**規則 V4（move）** 所有する値は、代入・値渡し・return で move する。

- move した元の変数は、代入し直すまで使えない（コンパイルエラー）。分岐の片方で move
  した場合も、合流した後は使えない。ただし `return`・`break` で抜ける分岐の move は、
  合流した後に影響しない。
- ループの中で、ループの外の変数を move してはいけない。次の周回で move 済みの値を使う
  ことになるため。同じ周回の中で代入し直すか、move の後でループを抜ける（`break`・
  `return`）なら許す。
- move した元はゼロになる。静的な検査が漏れても、同じ値を2回 drop しない。
- フィールドや配列の要素からも move できる。元の場所はゼロになる。ゼロ値のない型
  （`T^`）のフィールドからは move できないので、共有するか、別の値と入れ替える。

**規則 V5（drop）** 持ち主がいなくなった値は、1回だけ drop される。

- 変数は、スコープを出るとき（`return`・`break`・`continue`・`?` を含む）に、宣言と逆の
  順で drop される。
- 上書きされる値は、上書きの前に drop される。
- オブジェクトの中身は、参照数が0になったときに drop される（規則 O2）。
- drop は、まず型の `drop` メソッドを呼び、次にフィールドを宣言と逆の順で drop する。

**規則 V6（drop を書く）** `drop` は `impl Drop for T` で書く。`drop` はゼロ値を受け入れ、
ゼロ値には何もしない（ゼロ値は「空」の意味）。`drop` を直接呼んではいけない。

## 4. オブジェクトと共有

**規則 O1（new）** `new T { フィールド: 値, ... }` はヒープにオブジェクトを作り、共有
ポインタ `T^` を返す。省いたフィールドはゼロになる（ゼロ値のない `T^` のフィールドは
省けない）。確保に失敗すると trap する（規則 C3）。失敗を扱いたい所では
`try_new T { ... }` を使い、`Option<T^>` を受け取る。

**規則 O2（参照数）** オブジェクトは参照数を持つ。参照数は、そのオブジェクトを指す共有
ポインタの持ち主の数。参照数が0になると、中身を drop して（規則 V5）メモリを返す。

**規則 O3（共有できる値の代入）** 共有できる値の代入・値渡し・return は、rc モードでは
共有（参照数 +1）、owned モードでは move になる（規則 M2）。上書きとスコープの終わりで
参照数 −1。共有できる値を含む struct は、フィールドごとに同じ扱いになる。

**規則 O4（null がない）** 共有ポインタは必ずオブジェクトを指す。無いことがある所は
`Option<T^>` にし、`case` で取り出してから使う。`Option<T^>` の中身は1語で、None は内部で
0 になる。触るたびに null を調べる必要はない。`p.x` は共有ポインタの先のフィールドを
読み書きし、`p.f()` はメソッドを呼ぶ（メンバーの書き方は §13 で検討中）。

**規則 O5（weak）** `weak T^` は数えない共有ポインタで、フィールドにもグローバルにも置ける。
ゼロ値は「何も指さない」。読むと `Option<T^>` が返り、オブジェクトがもう解放されていれば
None になる。逆向きのポインタ（子から親、スレッドからプロセス）は weak にする。

**規則 O6（循環）** 共有ポインタの輪は、参照数が0にならないので解放されない（漏れ）。
漏れはメモリ安全を壊さない。デバッグ用の漏れ検査が、根からたどれないのに参照数が残って
いるオブジェクトを報告する。

**規則 O7（共有できる標準の型）** `String`・`Vec<T>`・`HashMap<K, V>` は、中身を参照数
つきのバッファに置く。共有した後に書き換えるとき、バッファが共有されていればそこで複製
する（コピーオンライト）。そのため共有しても値として振る舞い、片方の変更はもう片方に
見えない。

## 5. 借用

**規則 B1（作り方）** `&x` は共有借用 `borrow T` を、`&mut x` は可変借用
`borrow mut T` を作る。メソッドの receiver に要る `&` は自動で入る。

- 変数に `mut` の宣言は要らない。変数はすべて書き換えられる（C と同じ）。
- `const` の値は、書き換えも可変借用もできない。

**規則 B2（置ける場所）** 借用（と、借用を含む `Option`・`Result`）を置けるのは、
ローカル変数、引数、戻り値だけ。フィールド、グローバル、配列の要素、enum の payload、
`Option`・`Result` 以外のジェネリックの型引数には置けない。`str` も同じで、保存したい
文字列は `Text<N>` か `String` にする。ただし文字列リテラルは静的なので、どの関数からでも
返せる。

**規則 B3（寿命）** 借用は、それを持つ変数のスコープの終わりまで続く（レキシカル）。最後に
使った所では終わらない。

**規則 B4（共有借用）** 共有借用が続いている間は、次のことができない。

- 借用を通した書き換え（`r.x = 1`、`r.x++`、`&mut r.x`、`borrow mut` の receiver を
  とるメソッドの呼び出し）。
- 元の値の書き換え、move、可変借用。

**規則 B5（可変借用）** 可変借用が続いている間は、元の値を直接使えない（読むこともできない）。
同じ値をもう一度借用することもできない。

**規則 B6（戻り値の借用）** 借用を返す関数が返せるのは、最初の借用引数（メソッドなら
receiver）から借りたもの、グローバル、文字列リテラルだけ。呼び出し側では、結果が続いて
いる間、その引数に渡した値が借用されたままになる。

**規則 B7（ポインタの先の借用）** 共有ポインタの先にあるものは、別の共有ポインタから
書き換えられうる。そこで、共有ポインタの先にあるものを借用している間、コンパイラは借用
しているもの（オブジェクトと、その中の参照数つきバッファ）を共有して保持する。借用中に
別の経路から書き換えられても、借用しているメモリは解放されない。コピーオンライトの型は、
書き換えた側が複製を持つ。owned モードでも同じで、owned モードで暗黙に参照数を増やすのは
ここだけ。

**規則 B8（payload）** `case` で取り出した payload は、データならコピー、共有できる値なら
共有（owned では move）になる。共有ポインタの先にある enum から、所有する値の payload は
取り出せない。

**規則 B9（生ポインタへの変換）** 安全なソースでは、借用を生ポインタや整数アドレスとして
保存できない（変数・フィールドへの初期化と代入、構造体リテラル、生ポインタを返す
return）。保存した後は、何を借りているかを誰も追えなくなるため。これは生ポインタの操作の
一つとして扱い、ほかの操作と同じく移行の間は警告 W0003、移行が終わったらエラーにする
（規則 U1）。グローバルの借用（プログラムの終わりまで生きている）と、生ポインタの先の
借用（参照外しがすでに W0003）は対象外。関数の引数として渡すことは、MLC-023 で引数と
receiver を借用に移すまで報告しない。

## 6. モード

**規則 M1（宣言）** ファイル名に `.owned` を含むファイル（`fs.owned.mln`）は owned
モード、含まないファイルは rc モードになる。ファイル名の並びは
`<名前>.<構文>.<モード>.<安全性>.<役割>.mln`（例: `page.dom.owned.unsafe.test.mln`）。

**規則 M2（違い）** 2つのモードの違いは、共有できる値の代入・値渡し・return だけ。

- rc: 共有になる。ただし、その後使わない変数からの代入は move になる。
- owned: move になる。共有したい所では `x.share()` と書く。move した元を使うとコンパイル
  エラー（規則 V4 と同じ）。

**規則 M3（互換）** owned モードで通るファイルは、rc モードにしてもそのまま通り、同じに動く
（drop のタイミングも同じ）。rc から owned に切り替えると、暗黙に共有していた所が、すべて
コンパイルエラーとして出てくる。

**規則 M4（境界）** モードは型も表現も変えない。モードの違うモジュール同士は、変換なしで
呼び合える。owned のコードが持っているオブジェクトも、別のモジュールと共有されていることが
ある。解放は参照数で決まるので、それでも安全。

**規則 M5（ジェネリック）** ジェネリックの本体は、テンプレートを書いたファイルのモードと
安全性で検査し、コードを生成する。

**規則 M6（import）** import のパスには `.owned` と `.unsafe` を書かない。
`import fs from "fs.mln";` は、`fs.mln`・`fs.owned.mln`・`fs.unsafe.mln`・
`fs.owned.unsafe.mln` のうち、あるものを読む。2つ以上あればエラー。モードと安全性は
そのファイルの中の書き方の話で、使う側には関係ない（規則 M4、U3）。そのため、モードを
切り替えてもファイル名を変えるだけで済み、import している側は直さなくてよい。

例（同じ処理を2つのモードで書いたもの）:

```c
struct Node {
    i32 id;
    weak Node^ parent;
    Vec<Node^> children;
};

void attach(Node^ parent, Node^ child) {
    child.parent = parent;        // weak は数えない
    parent.children.push(child);  // child を渡す
}

// rc モード
Node^ root = new Node { id: 0 };
Node^ leaf = new Node { id: 1 };
attach(root, leaf);               // root は後でも使うので共有、leaf は最後の使用なので move

// owned モード（ファイル名が .owned.mln）
attach(root.share(), leaf);       // 共有する所を書く
```

## 7. unsafe

**規則 U1（生ポインタ）** 生ポインタ `T*` は数えられないデータ。参照外し（`*p`・`p->x`・
`p[i]`）、ポインタ演算、ポインタとのキャスト、整数アドレスとの変換は、unsafe なファイル
でだけ書ける。安全なファイルでは警告 W0003 になり、移行が終わったらエラーにする。

**規則 U2（宣言）** unsafe なファイルは、ファイル名に `.unsafe` を含む（`heap.unsafe.mln`、
`heap.owned.unsafe.mln`）。import のパスには書かない（規則 M6）。

**規則 U3（境界）** unsafe なファイルが公開する関数は、値・借用・共有ポインタ・`Option`
を受け渡し、生ポインタを見せない。安全なファイルは生ポインタを受け取っても参照外しできない
ので、境界は型で守られる。

## 8. 実行時検査と trap

**規則 C1（添字）** 固定長配列の添字は範囲検査する。定数の添字が範囲外ならコンパイル
エラー（E0304）、計算した添字は実行時に検査する（`chk` 命令）。

**規則 C2（null）** 安全なコードには null がない。共有ポインタは必ずオブジェクトを指し、
無いことは `Option` で表す（規則 V1、O4）。生ポインタの null は unsafe の範囲。

**規則 C3（確保）** `new` の確保に失敗すると trap する。

**規則 C4（trap の動作）** trap ではプログラムが止まり、r1 に `0x1BAD00 | 種類` が入る。
ユーザープロセスならそのプロセスが終わり、カーネルならマシンが止まる。

| 種類 | r1 | 意味 |
| --- | --- | --- |
| `0x01` | `0x1BAD01` | 添字が範囲外 |
| `0x02` | `0x1BAD02` | 確保の失敗（予定） |

## 9. スレッドと割り込み

**規則 T1（atomic）** 複数のスレッドを持つプロセスとカーネルでは、参照数の増減を atomic
にする。1スレッドのプロセスでは atomic にしない。

**規則 T2（共有する変数）** 同じ変数（共有ポインタを入れたグローバルやフィールド）を複数の
スレッドが読み書きするときは、ロックで守る。これはコンパイラが検査しない約束で、破ると
メモリ安全が崩れうる。スレッド間の受け渡しには、チャネルや同期用の型を使う。

**規則 T3（割り込み）** 割り込みハンドラの中で参照数が0になったオブジェクトは、その場で
解放せず、割り込みの外でまとめて解放する。割り込みハンドラの中では `new` しない。

## 10. 決めたことと理由

| 項目 | 決めたこと | 理由 |
| --- | --- | --- |
| 共有ポインタの書き方 | 検討中（§13） | - |
| null | なし。無いことは `Option<T^>`（None）で表す | 「無い」の書き方が1つになる。チェックの漏れがコンパイルエラーになり、触るたびの null の検査も要らない。1語に収まるのでコストも増えない |
| weak の読み出し | `Option<T^>`（解放済みなら None） | 同上 |
| モードと unsafe の印 | ファイル名の `.owned` / `.unsafe`。import のパスには書かない | 今の `.dom` / `.test` / `.contract` と揃い、ファイル一覧で分かる。import に書かないので、切り替えても使う側は変わらない |
| `mut` 宣言 | 要らない | 変数はもともと書き換えられ、`mut` を書いたコードはない |
| 標準のコンテナ | コピーオンライト | rc では気軽にコピーでき、owned では move-only に見える。規則 B7 の保持もこれで安全になる |
| 切り替えの単位 | ファイル（モジュール） | ビルド全体だと全部を owned で書くしかない。型ごとだと所有用と共有用の型が2つずつ要る |

検討して採らなかったもの:

- **Rust 風の引数の渡し方（`mut` / `own`）と、可変グローバルの禁止。** ポインタのグラフ、
  グローバル、クロージャ、コンテナを借りるイテレータを失うため。
- **tracing GC。** 回収中の停止があり、解放のタイミングが決まらない。
- **言語を層ごとに分けること。** コンパイラ・LSP・標準ライブラリ・テストの道具が2倍になる。
