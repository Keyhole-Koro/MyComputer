## 0. 一言で

- **安全なコードにはポインタがない。すべては値。** 代入は「コピー」の意味で、`b = a` の後に
  `b` を書き換えても `a` は変わらない。
- **書き換えられるのは、自分のローカル変数、`borrow` で借りた呼び出し元の変数、名前で
  指したグローバルだけ。** 関数を読めば、何が変わりうるかが署名と本文だけで分かる。
- **ヒープを使うのは `new`（`Box<T>`）、`String`、`Vec<T>`、`Map<K, V>`。** コピーは共有で
  済ませ、書き換える時に必要ならコンパイラがコピーする。書き手には見えない。
- **つながりと識別は、プールとハンドル（番号）で表す。** 向きは自由で、輪になってもよい。
- **解放はコンパイラがする。** 最後の持ち主が手放した時に消える。値は輪を作れないので、
  必ず消える。`delete` も `weak` も `own` もない。

人が覚える言葉は、今あるものに `new` と `Box<T>`、標準ライブラリの `Pool<T, N>` と
`Handle<T>` が加わるだけ。消えるのは、安全なコードのポインタ（`T*`、`*`、`&` のアドレス、
`->`）と `impl Copy`。

## 1. 方針

- **メモリ安全。** 安全なソースからは、解放済みのメモリ、範囲外、初期化されていないメモリに
  触れない。触れようとすれば、コンパイルエラーか trap になる。
- **仕様が小さい。** 安全のための規則は「代入はコピー」「借用は関数の中だけ」の2つから
  導かれる。
- **見渡しがよい。** 遠くの何かが書き換わることがない。変わるのは、目の前の変数と、`borrow`
  と書いた引数と、名前で書いたグローバルだけ。
- **カーネルでも使える。** `new`・`String`・`Vec` を使わなければ、ヒープは一切動かない。
  固定長の `Text<N>`、配列、`Pool<T, N>` だけで書ける。
- **構文は今の C 風のまま。** trait もそのまま。

## 2. 用語

| 用語 | 意味 |
| --- | --- |
| 値 | 変数・フィールド・配列の要素に入っているもの。すべての型は値 |
| データ | 整数、bool、enum、関数値、`Text<N>`、ハンドルと、それだけでできた struct・配列 |
| 共有値 | 中身をヒープに置く値。`Box<T>`、`String`、`Vec<T>`、`Map<K, V>` と、それを含む struct・配列 |
| 所有値 | `drop` を持つ型（資源）。コピーできず、move だけ |
| 持ち主 | 値を入れている場所（変数、フィールド、要素） |
| 借用 | 持ち主を変えずに、書き換えるために場所を貸すこと。`borrow T` |
| ハンドル | プールの中の1つを指す番号（と世代）。データ |
| プール | ハンドルで指せる値の入れ物。`Pool<T, N>`（固定長）、`Table<T>`（伸びる） |
| trap | 実行時検査の失敗で、プログラムを止めること |

## 3. 値の種類

**規則 V1（ゼロ値）** 変数・フィールド・配列の要素は、初期化しなければゼロで始まる。整数は
0、bool は false、enum は数値 0、`Option` は None、`String`・`Vec`・`Map` は空、struct と
配列は要素ごとにゼロ。`Box<T>` にはゼロ値がない。`Box<T>` の変数・フィールドは必ず初期化し、
無いことがある所は `Option<Box<T>>` にする。

**規則 V2（種類）** 値の種類は型から自動で決まる。宣言は要らない。

| 種類 | 代入・return |
| --- | --- |
| データ | ビットごとのコピー |
| 共有値 | 意味はコピー。実装は共有（規則 H3） |
| 所有値 | move（規則 V4） |

struct・配列・enum の種類は、中身のうちいちばん強い種類になる（所有値 ＞ 共有値 ＞
データ）。データの配列はデータで、配列を持つ struct も同じ。

共有値を実装するまでは、生ポインタのフィールドを持つ struct も move する。`Vec` にはまだ
`drop` がなく、ヘッダをコピーするとバッファを2か所から指してしまう（MLC-025）。

**規則 V3（代入はコピーの意味）** `b = a` の後、`a` と `b` は別の値。どちらを書き換えても
もう一方は変わらない。引数、return、フィールドへの代入、コンテナへの追加、`case` で
取り出す payload も同じ。

**規則 V4（move）** 所有値は、代入・return と `move T x` の引数で move する。

- move した元の変数は、代入し直すまで使えない（コンパイルエラー）。`return`・`break` で
  抜ける分岐の move は、合流した後に影響しない。
- ループの中で、ループの外の変数を move してはいけない。同じ周回で代入し直すか、move の後
  でループを抜けるなら許す。
- move した元はゼロになる。静的な検査が漏れても、同じ資源を2回 drop しない。
- フィールドや配列の要素からも move できる。元の場所はゼロになる。

**規則 V5（drop）** 所有値は、持ち主がいなくなった時に1回だけ drop される。変数はスコープを
出る時（`return`・`break`・`continue`・`?` を含む）に宣言と逆の順で、上書きされる値は上書き
の前に、コンテナの中の値はコンテナと一緒に。drop は、まず型の `drop` メソッドを呼び、次に
フィールドを宣言と逆の順で drop する。

**規則 V6（drop を書く）** `drop` は `impl Drop for T` で書く。`drop` はゼロ値を受け入れ、
ゼロ値には何もしない。`drop` を直接呼んではいけない。

## 4. 書き換え

**規則 W1（書き換えられる場所）** 書き換えられるのは、次の場所と、そこから値として
たどれるフィールド・要素・`Box` の中身だけ。

- 自分のローカル変数と、無印か `move` で受け取った引数（無印の引数を書き換えても、呼び出し元は
  変わらない）
- `borrow` で受け取った引数（呼び出し元の場所がそのまま変わる）
- 名前で書いたグローバル

ほかに書き換える手段はない。関数が変えうるものは、署名（`borrow` の引数）と本文
（ローカルとグローバルの名前）に全部現れる。

**規則 W2（書く前にコピー）** 共有値の中身を書き換える時、その中身がほかの値と共有されて
いれば、コンパイラが書く前にコピーする。書き手は意識しない。共有されていなければ、その場で
書き換わる。

```c
Vec<i32> a = ...;
Vec<i32> b = a;      // 共有（コピーしない）
b.push(1);           // ここでコピーしてから追加。a は変わらない
a.push(2);           // a はもう誰とも共有していないので、その場で追加
```

**規則 W3（`const`）** `const` の値は、書き換えも借用もできない。

## 5. 引数と借用

引数の渡し方は3つ。読むのが既定で、書くときと受け取るときだけ印を付ける。

| 書き方 | 意味 |
| --- | --- |
| `T x` | 読む。呼び出し元の値はそのまま残る |
| `borrow T x` | 書き換える。呼び出し元の場所を借りる |
| `move T x` | 受け取る。以後の持ち主は呼び出し先 |

**規則 P1（読む）** 無印の引数は読むだけ。構造体と配列をコピーするか番地で渡すかはコンパイラが
決める。書き手からはコピーに見える（規則 V3）。

- 本文が書き換える引数は、入口でコピーを取る。呼び出し元は変わらない。
- 所有値はコピーできない。無印の引数の所有値は読むだけで、書き換えも move もコンパイルエラー
  になる。持ち主は呼び出し元のままで、drop も呼び出し元でする。
- 呼び出しが作った所有値を、読むだけの引数へそのまま渡すことはできない。drop する持ち主が
  いないので、変数に入れてから渡す。
- `borrow T` の変数を無印の引数へ渡すと、借りている値を読む。

**規則 P2（受け取る）** `move T x` の引数は所有値を受け取る。渡した元の変数は使えなくなり
（規則 V4）、drop は呼び出し先でする。データと共有値を渡す場合は無印と同じ。コンテナへ入れる
`push(move T value)` のように、値を保管する関数に付ける。`move` に借用やポインタは渡せない。

借用は、値をコピーも move もせずに、書き換えるために呼び出し先へ場所を貸す仕組み。

**規則 B1（作り方）** `&x` は `borrow T` を作る。メソッドの receiver に要る `&` は自動で入る。
`x` はローカル変数・引数・グローバルと、そこからたどれるフィールド・要素・`Box` の中身。

**規則 B2（置ける場所）** 借用（と、借用を含む `Option`・`Result`）を置けるのは、引数、
ローカル変数、戻り値だけ。フィールド、グローバル、配列の要素、enum の payload、`Box`、
コンテナ、`Option`・`Result` 以外のジェネリックの型引数には置けない。`str` も同じ。

**規則 B3（寿命）** 借用は、それを持つ変数のスコープの終わりまで続く（レキシカル）。

**規則 B4（借用中）** 借用が続いている間は、元の値を直接使えない。読むことも、書き換えも、
move も、もう一度借りることもできない。

**規則 B5（借用を通した借用）** 借用を通して取った借用は、通った借用もロックする。

**規則 B6（戻り値の借用）** 借用を返す関数が返せるのは、最初の借用引数（メソッドなら
receiver）から借りたもの、グローバルの一部、文字列リテラルだけ。無印の引数からは返せない。呼び出し側では、結果が
続いている間、その引数に渡した値が借用されたままになる。

**規則 B7（グローバルの借用）** グローバルの中の共有値を借りている間、コンパイラはその中身
（ヒープのバッファ）を保持する。借りている間に別の関数がそのグローバルを書き換えても、
借用が指すメモリは解放されない。見える値が古くなることはあるが、メモリは壊れない。
ローカル変数と引数の借用は、規則 B4・B5 で静的に守られるので保持しない。

**規則 B8（呼び出しの引数）** 1回の呼び出しで、`&` で渡す場所は、ほかの引数と重なっては
いけない（コンパイルエラー）。

## 6. ヒープの値

**規則 H1（new）** `new T { フィールド: 値, ... }` は値をヒープに置き、`Box<T>` を返す。
省いたフィールドはゼロになる。`b.x` と `b.f()` は中身のフィールドとメソッドに届く。`*b` で
中身の値を取り出せる（コピー）。再帰する型は `Box` を通す。

```c
struct Node { i32 value; Option<Box<Node>> next; };
Box<Node> list = new Node { value: 1, next: Some(new Node { value: 2 }) };
```

**規則 H2（標準の共有値）** `String`、`Vec<T>`、`Map<K, V>` は共有値。中身はヒープにある。
成長するときに確保し、失敗は戻り値で返す（今の `push` と同じ）。

**規則 H3（共有）** 共有値のコピーは、中身を共有する（O(1)）。書き換える時に必要なら
コピーする（規則 W2）。書き手からはコピーに見える（規則 V3）。

**規則 H4（解放）** ヒープの中身は、最後の持ち主が手放した時（上書き、スコープの終わり、
コンテナからの削除、コンテナの解放）に解放される。値は自分自身を含められないので、共有値は
輪を作れない。だから必ず解放される。

**規則 H5（確保の失敗）** `new` は確保に失敗すると trap する（規則 C3）。失敗を扱いたい所
では `try_new T { ... }` を使い、`Option<Box<T>>` を受け取る。

**規則 H6（ヒープを使わない書き方）** `Text<N>`、配列、`Pool<T, N>`、データだけの struct は
インラインに置かれ、ヒープを使わない。`new`・`String`・`Vec`・`Map`・`Table` を使わない
モジュールは、ヒープに一切触れない。

## 7. 識別とつながり

言語には「同じ物」という概念がない。2つの変数が同じ物を指すことはなく、値は常にそれぞれの
もの。識別が要るもの（DOM のノード、プロセス、ファイル、グラフの頂点）は、プールに入れて
ハンドルで指す。

**規則 I1（プール）** `Pool<T, N>` は最大 N 個の T を持つ値（インライン）。`Table<T>` は同じ
API で伸びる（ヒープ）。どちらも標準ライブラリの型で、言語の仕組みではない。

| 操作 | 意味 |
| --- | --- |
| `insert(value) -> Option<Handle<T>>` | 入れてハンドルを返す。一杯なら None |
| `get(h) -> Option<borrow T>` | 借りる。消えていれば None |
| `remove(h) -> Option<T>` | 取り出して空ける。以後そのハンドルは None になる |
| `for (T v in pool)` | 生きているものを順に |

**規則 I2（ハンドル）** `Handle<T>` は番号と世代からなるデータ。自由にコピーでき、どこにでも
置ける。プールの中の値が別のハンドルを持てば、つながりになる。向きは自由で、輪になってもよい。

**規則 I3（古いハンドル）** `remove` した場所が再利用されても、古いハンドルは世代が違うので
None を返す。コンパイラはハンドルを追跡しない。安全はプールの検査で守る（規則 C2）。

**規則 I4（つながりの手入れ）** `remove` しても、ほかの値が持つハンドルは直らない。古い
ハンドルは None になるだけ。親子や前後の手入れは、プールを使う側が行う。手で書かずに宣言から
生成するのがモデル拡張（`mylang-model.md`）で、言語の規則は増えない。

## 8. グローバル

**規則 G1** グローバルは、ゼロで始まる値の変数。ローカル変数と同じように読み書きできる。

**規則 G2** 所有値（資源）のグローバルは、プログラムの終わりまで drop されない。

## 9. 実行時検査と trap

**規則 C1（添字）** 固定長配列の添字は範囲検査する。定数の添字が範囲外ならコンパイルエラー
（E0304）、計算した添字は実行時に検査する（`chk` 命令）。

**規則 C2（ハンドル）** プールは、ハンドルの番号が範囲内で、世代が一致する時だけ値を返す。

**規則 C3（確保）** `new` の確保に失敗すると trap する。

**規則 C4（trap の動作）** trap ではプログラムが止まり、r1 に `0x1BAD00 | 種類` が入る。
ユーザープロセスならそのプロセスが終わり、カーネルならマシンが止まる。

| 種類 | r1 | 意味 |
| --- | --- | --- |
| `0x01` | `0x1BAD01` | 添字が範囲外 |
| `0x02` | `0x1BAD02` | 確保の失敗（予定） |

## 10. unsafe

**規則 U1（生ポインタ）** 生ポインタ `T*` は数えられないデータ。参照外し（`*p`・`p->x`・
`p[i]`）、ポインタ演算、ポインタとのキャスト、整数アドレスとの変換、借用を生ポインタとして
保存することは、`.unsafe.mln` でだけ書ける。安全なファイルではエラー E0701 になる。

**規則 U2（境界）** unsafe なファイルが公開する関数は、値・借用・ハンドル・`Option` を受け
渡し、生ポインタを見せない。安全なファイルは生ポインタを受け取っても参照外しできないので、
境界は型で守られる。標準ライブラリの共有値の中身（`Vec` のバッファなど）は unsafe で書かれ、
信頼する部分になる。

**規則 U3（import）** import のパスには `.unsafe` を書かない。`import fs from "fs.mln";` は
`fs.mln` か `fs.unsafe.mln` のあるほうを読む。両方あればエラー。

**規則 U4（`safe`）** unsafe なファイルの関数を安全なファイルから呼べるのは、`safe` と印を
付けたものだけ。`safe` は「この関数は引数が何であってもメモリを壊さない」と人が保証する印で、
コンパイラは検査しない。`mem.write_word(i32 addr, i32 value)` のように整数で番地を受ける関数
は値しか受け渡さないので規則 U2 では止まらない。だから印を既定で無しにする。印の一覧が信頼
する部分の一覧になる。アセンブリの関数も同じ扱いで、安全なファイルからは呼べない。

**規則 U5（型）** 安全なファイルには `T*` という型を書けない。`.contract.mln` の構造体の
フィールドだけは例外で、これは通信の形を表すだけで、辿るのは unsafe なコードに限られる。
`@safe` の関数は署名に生ポインタを持てない（E0702）。

## 11. スレッドと割り込み

**規則 T1（共有しない）** スレッドの間で値を渡すと、それぞれの値になる（規則 V3）。同じ
メモリを2つのスレッドが書き換える手段は、標準ライブラリの同期用の型（Mutex、チャネル）
だけ。

**規則 T2（カウントの atomic）** 複数のスレッドを持つプロセスとカーネルでは、共有値の
実装のカウントを atomic にする。1スレッドのプロセスではしない。

**規則 T3（割り込み）** 割り込みハンドラの中では `new` も、共有値の成長もしない。割り込みの
中で解放すべきものは、割り込みの外でまとめて解放する。

## 12. なぜ安全か

安全なコードがメモリに触る道は、変数（ローカル・引数・グローバル）、借用、共有値の中身、
ハンドルの4つしかない。

1. **変数。** 自分の持ち物。ゼロで始まり（V1）、スコープで消える。
2. **借用。** ローカルと引数への借用は、関数の外に出ず（B2）、借りている間は元が変わらない
   （B4・B5）。グローバルへの借用は、指すメモリを保持する（B7）。
3. **共有値の中身。** 最後の持ち主が手放すまで解放されない（H4）。書き換える側がコピーする
   （W2）ので、ほかの持ち主の見ている中身が途中で変わったり消えたりしない。輪がないので
   漏れない。
4. **ハンドル。** 触るたびにプールが検査し、消えたものは None になる（C2）。
5. **添字。** 範囲検査する（C1）。
6. **スレッド。** 値は共有されない（T1）。

残りの責任は `.unsafe.mln` と標準ライブラリの中身にだけある。

## 13. コンパイラと実行時がやること

書き手が書かない部分。

| 仕事 | 内容 |
| --- | --- |
| 表現 | データはインライン、共有値はヒープの中身への1語 |
| カウント | 共有値の中身は持ち主の数を数える。コピーで +1、手放すと −1、0 で解放。書き手には見えない |
| 省略 | 無印と `borrow` の引数は数えない。最後の使用はコピーでなく move にする。関数の中で増やして減らす組は消す |
| 書く前にコピー | 共有値の中身への書き込みの前に、持ち主が自分だけか確かめ、違えばコピー（W2） |
| その場で書き換え | 持ち主が自分だけなら、ヒープの中身をその場で書き換える |
| 借用の保持 | グローバルの共有値への借用の間、中身を保持する（B7） |
| ゼロ初期化、drop、範囲検査 | 実装済み |

自作の CPU なので、カウントの増減と「0 なら分岐」を1命令にできる。

## 14. 書き味

**アプリ（イベントハンドラ）。** 今の `c->clicks += c->step` は、借用でほぼそのまま書ける。
フレームワークが app の状態を持ち、ハンドラに `&` で貸す。

```c
struct Counter { i32 clicks; i32 step; };

void (borrow Counter c) click(i32 id) {
    c.clicks = c.clicks + c.step;      // 呼び出し元の状態がその場で変わる
}
```

**DOM サーバ。** ノードはプールに入れ、番号で指す。親・子・兄弟はハンドル。

```c
struct Node { u16 kind; Text<32> name; Option<Handle<Node>> parent;
              Option<Handle<Node>> first_child; Option<Handle<Node>> next_sibling; };
Pool<Node, 512> g_nodes;

Result<Handle<Node>, UiError> create_node(u16 kind, str name) {
    Node n = Node { kind: kind };
    n.name.append(name);
    return case g_nodes.insert(n) of {
        Some(h) -> Ok(h);
        None -> Err(UiError::NodeIdLimit);
    };
}

void set_text(Handle<Node> h, str text) {
    case g_nodes.get(h) of {
        Some(n) -> ({ n.name.clear(); n.name.append(text); });
        None -> _;                     // 消えたノード。何もしない
    };
}
```

今の `heap.alloc`、`(Node *)` へのキャスト、約30行のゼロ埋め、`g_node_table[id] = n` が消える。

**つながり。** 片方向のリストや木は `Box`。双方向や親へのつながり、グラフはプール。

```c
// 片方向：Box。コピーは共有、書き換える時にコピー
struct Item { i32 v; Option<Box<Item>> next; };

// 双方向：プールとハンドル。向きは自由
struct Entry { i32 v; Option<Handle<Entry>> prev; Option<Handle<Entry>> next; };
Pool<Entry, 64> g_list;
```

今の `IntrusiveList<T>`（`T *head`、`&n->next`）は生ポインタで書かれている。値のモデルでは、
カーネルのスレッド表（`Option<Thread> g_threads[256]` と slot 番号）と同じく、プールと
ハンドルで書く。

**カーネル。** 状態はグローバルの値（表、プール、`Text<N>`）で、関数が名前で書き換える。
ヒープは使わない。MMIO・ページ表・コンテキスト切り替えは `.unsafe.mln`。

## 15. 今の実装との対応

| 今あるもの | 扱い |
| --- | --- |
| 借用の置き場所の規則、衝突の検査（MLC-023、MLC-024） | そのまま規則 B2〜B6、B8 |
| 範囲検査、ゼロ初期化、enum の網羅性 | そのまま規則 C1、V1 |
| `Drop`、持ち主フラグ、move の検査 | そのまま規則 V4〜V6。持ち主フラグは「元をゼロにする」に置き換える |
| データだけの struct の自動コピー | そのまま規則 V2 |
| `str`、`Text<N>`、`String` | そのまま。`String` の中身を共有値にする |
| `.unsafe.mln`、E0701 | 規則 U1 |
| `impl Copy` | 削除した。種類は規則 V2 で型から決まる |
| 安全なコードの `T*`、`->`、`&` のアドレス取得 | unsafe へ |
| `heap.alloc` / `heap.free` の直接の呼び出し | `new`、`Vec`、`Pool` へ |

新しく作るもの: `new` と `Box<T>`、共有値のカウントと「書く前にコピー」、`Pool`・`Table`・
`Handle`・`Map`、グローバルの借用の保持、import での `.unsafe` の省略。

## 16. 代償

- **カウントのコスト。** 共有値のコピーと解放で数命令。無印と `borrow` の引数、最後の使用では
  省ける。CPU に命令を足せばさらに減る。
- **書く前のコピー。** 共有している大きな値を書き換えると、その部分がコピーされる。状態を
  2か所から持つ書き方を避けるか、`borrow` で1か所から書き換える。
- **つながりはプール経由。** `h.next` ではなく `pool.get(h)` と `case` を書く。今の DOM・
  カーネルの書き方と同じ。
- **識別がない。** 「同じ物」が要るものは、必ずプールに入れる。
- **標準ライブラリの作り直し。** `String`・`Vec`・`Map` を共有値に、`Pool`・`Table` を追加。

## 17. 未決事項

- `new` の綴り（`new T { ... }` か `Box::new(T { ... })` か）と、`*b` で中身を取り出す書き方。
- `Pool` / `Table` / `Handle` の API の細部（イテレータ、`Handle` の表現）。
- グローバルの借用の保持（B7）のコストと、保持しないで済む場合の判定。
- カウントの増減を CPU の命令にするか。
- `Option<Box<T>>` と `Option<Handle<T>>` を1語に収める表現。
- 可変長の列。今は標準の `Blob`（`mylang-model.md` §6）で持つ。共有値（§6）を実装したら、
  どちらかに寄せるかを決める。
