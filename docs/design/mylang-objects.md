## 0. 一言で

- **型は2種類。** `struct` は値（今のまま）。`object` は実体で、変数はハンドル1語を持つ。
- **寿命は親が決める。** `new(親) T { ... }`。親が消えれば子孫も消える。早く消したい時だけ
  `delete`。
- **ハンドルはどこにでも置ける。** 数えない。向きは自由で、輪になってもよい。
- **消えた相手に触った時だけ、実行時に分かる。** `Option<T>` なら None、`T` なら trap。
- 人が覚える言葉は `object`・`new(親)`・`delete` の3つ。`own`・`weak`・`share`・モード・
  参照数・ライフタイムはない。

## 1. 人が書くこと、コンパイラ・実行時がやること

| 人が決めること | いつ |
| --- | --- |
| `struct` か `object` か | 型ごとに1回 |
| `new(親)` の親 | 作る時 |
| `Option<T>` か `T` か | フィールドごと（今も決めている） |
| `delete` | まれ（ウィンドウを閉じる、ノードを1つ消す） |

| コンパイラ・実行時がやること |
| --- |
| 触るたびに、相手が生きているかと位置が中かを確かめる（CPU の1命令） |
| `Option<T>` を読む時、消えていれば None にする |
| 親が消えた時に、子孫をまとめて消す |
| ブロックの子（親なしで作ったもの）を、ブロックの終わりで消す |
| `delete` の後の使用、値の move と借用の衝突をコンパイルエラーにする |
| 値（`String`・`Vec`・資源）の drop を、上書き・スコープの終わり・親の削除で行う |

## 2. 用語

| 用語 | 意味 |
| --- | --- |
| 値 | 変数・フィールド・要素に直接入っているもの。`struct`、整数、`Text<N>`、`String`、`Vec` |
| オブジェクト | `object` 型の実体。ヒープに置かれ、ハンドルで指す |
| ハンドル | オブジェクトを指す1語。世代と番号からなるデータ |
| 親 | オブジェクトの寿命を決めるオブジェクト。親が消えると子孫も消える |
| 死んだハンドル | 指していたオブジェクトがもう消えているハンドル |
| 借用 | 値の場所を呼び出し先に貸すこと。`borrow T` / `borrow mut T` |
| trap | 実行時検査の失敗で、プログラムを止めること |

## 3. オブジェクト

**規則 O1（object）** `struct` で宣言した型は値、`object` で宣言した型はオブジェクト。
object 型の変数・フィールド・要素は、ハンドル1語を持つ。

```c
object Window { Text<32> title; Vec<Node> nodes; };
object Node   { String text; Option<Node> next; Window win; };
```

**規則 O2（new）** `new(親) T { フィールド: 値, ... }` はオブジェクトを作り、ハンドルを返す。
親はオブジェクト（プロセスの根は `root`）。`new T { ... }` と親を省くと、今のブロックが親に
なり、ブロックを出る時に消える（`return`・`break`・`?` を含む）。省いたフィールドはゼロに
なる。確保に失敗すると trap する。失敗を扱いたい所では `try_new` を使い、`Option<T>` を
受け取る。

**規則 O3（delete）** `delete x` は x と、その子孫をすべて消す。順番は、x の `drop` → x の
値のフィールドの drop → 子（作った逆順に、同じ規則で）。同じ関数の中で `delete x` の後に
`x` を使うと、move 後の使用と同じコンパイルエラーになる。

**規則 O4（adopt）** `adopt(新しい親, x)` は x の親を変える（子孫ごと移る）。x の子孫を
新しい親にしようとすると trap する。「このブロックで作って、うまくいったら残す」は、
`new T { ... }` で作って最後に `adopt` する形で書く（今のガードの `keep()` に当たる）。

**規則 O5（ハンドル）** ハンドルはデータ。自由にコピーでき、フィールド・グローバル・配列・
コンテナ・関数値のどこにでも置ける。数えないので、何本あっても、輪になってもよい。
`a == b` は同じオブジェクトかどうか。ハンドルにゼロ値はないので、object 型の変数・
フィールドは必ず初期化する。無いことがある所は `Option<T>` にする（1語に収まり、None は 0）。

**規則 O6（死んだハンドル）** 消えたオブジェクトに触ると、読む場所の型で動きが決まる。

| 書き方 | 相手が消えていた時 |
| --- | --- |
| `Option<T>` | 読むと None |
| `T` | 触ると trap |
| `alive(h)` | 偽（止まらない） |

人が選ぶのは「無いことがあるか」だけ。長生きするものへのハンドル（子から親、ノードから
ウィンドウ）は `T`、消えうるものへのハンドル（親から子、グローバルから今のウィンドウ）は
`Option<T>` にする。

**規則 O7（drop）** object は `drop` を持てる。消える時に1回だけ呼ばれる。ファイルや
ウィンドウのような資源を持つ型は、これで閉じる。

## 4. 値

**規則 V1（ゼロ値）** 変数・フィールド・配列の要素は、初期化しなければゼロで始まる。整数は
0、bool は false、enum は数値 0、`Option` は None、`String`・`Vec` は空、struct と配列は
要素ごとにゼロ。ハンドルは例外（規則 O5）。

**規則 V2（種類）** 値の種類は型から自動で決まる。`impl Copy` は要らない。データ（整数、
bool、enum、関数値、`Text<N>`、ハンドルと、それだけでできた struct・配列）はコピー。
`drop` を持つ型と、それを含む型（`String`、`Vec<T>`、資源）は move。

**規則 V3（値の持ち主）** 値の持ち主は、それを入れている場所（ローカル変数、引数、
グローバル、オブジェクトのフィールド、配列の要素、コンテナ）。持ち主がいなくなった時に
drop される。オブジェクトのフィールドの値は、そのオブジェクトが消える時に drop される。

**規則 V4（move）** move した元の変数は、代入し直すまで使えない。`return`・`break` で抜ける
分岐の move は、合流した後に影響しない。ループの中で、ループの外の変数を move してはいけない
（同じ周回で代入し直すか、move の後で抜けるなら許す）。move した元はゼロになる。

**規則 V5（drop）** 所有値は1回だけ drop される。変数はスコープを出る時に宣言と逆の順で、
上書きされる値は上書きの前に。drop は、まず型の `drop` メソッドを呼び、次にフィールドを
宣言と逆の順で drop する。`drop` はゼロ値を受け入れ、ゼロ値には何もしない。直接呼んでは
いけない。

## 5. 参照渡し（借用）

**規則 B1（作り方）** `&x` は `borrow T` を、`&mut x` は `borrow mut T` を作る。メソッドの
receiver に要る `&` は自動で入る。変数に `mut` の宣言は要らない。`const` の値は書き換えも
可変借用もできない。

**規則 B2（置ける場所）** 借用（と、借用を含む `Option`・`Result`）を置けるのは、引数、
ローカル変数、戻り値だけ。フィールド、グローバル、配列の要素、enum の payload、オブジェクト、
`Option`・`Result` 以外のジェネリックの型引数には置けない。`str` も同じ。

**規則 B3（寿命）** 借用は、それを持つ変数のスコープの終わりまで続く（レキシカル）。

**規則 B4・B5（衝突）** 共有借用が続いている間は、借用を通した書き換えも、元の値の
書き換え・move・可変借用もできない。可変借用が続いている間は、元の値を直接使えない。
借用を通して取った借用は、通った借用もロックする。

**規則 B6（戻り値の借用）** 借用を返す関数が返せるのは、最初の借用引数（メソッドなら
receiver）から借りたもの、グローバルの一部、文字列リテラルだけ。

**規則 B7（オブジェクトの中の借用）** オブジェクトのフィールドを借りている間に、そのオブジェクト
が消えることがある。借用はハンドルと位置で表し、触るたびに規則 C2 の検査を通る。消えていれば
trap する。ローカル変数と引数の借用は、規則 B2〜B5 で静的に守られるので検査しない。

**規則 B8（呼び出しの引数）** 1回の呼び出しで、`&mut` で渡す場所は、ほかの引数と重なっては
いけない。

## 6. 実行時検査と trap

**規則 C1（添字）** 固定長配列の添字は範囲検査する。定数の添字が範囲外ならコンパイルエラー
（E0304）、計算した添字は実行時に検査する（`chk` 命令）。

**規則 C2（ハンドル）** ハンドルを通してオブジェクトに触るたびに、そのオブジェクトが生きて
いるかと、触る位置がオブジェクトの中かを確かめる。消えていれば規則 O6 のとおり。位置が外なら
trap する。

**規則 C3（確保）** `new` の確保に失敗すると trap する。

**規則 C4（trap の動作）** trap ではプログラムが止まり、r1 に `0x1BAD00 | 種類` が入る。
ユーザープロセスならそのプロセスが終わり、カーネルならマシンが止まる。

| 種類 | r1 | 意味 |
| --- | --- | --- |
| `0x01` | `0x1BAD01` | 添字が範囲外（実装済み） |
| `0x02` | `0x1BAD02` | 消えたオブジェクトに触った |
| `0x03` | `0x1BAD03` | オブジェクトの外に触った |
| `0x04` | `0x1BAD04` | 確保の失敗 |

## 7. 実装

### 7.1 オブジェクト表とハンドル

プロセスごとに1つ、カーネルにも1つ。1行16バイト。

| 語 | 中身 |
| --- | --- |
| 0 | オブジェクトのアドレス |
| 1 | 今のハンドルの値（空きなら 0） |
| 2 | オブジェクトの大きさ |
| 3 | 親の番号 |

ハンドルは32ビットで、上の12ビットが世代、下の20ビットが行の番号。0 は使わない（None に
当てる）。消す時に世代を1増やし、行を空きに戻す。世代が一周した行は二度と使わない。捨てる
のは表の16バイトだけで、オブジェクトのメモリはすぐ再利用できる。子の並び（最初の子、次の
兄弟）は、オブジェクトの前の見えない8バイトの頭に持つ。

### 7.2 CPU の命令

| 命令 | 動き |
| --- | --- |
| `ldh rD, rH, imm` | ハンドル rH のオブジェクトの位置 imm から1語読む。消えていれば trap |
| `sth rS, rH, imm` | 同じ場所へ1語書く |
| `ldhb` / `sthb` | 1バイト版 |
| `ldhx rD, rH, rO` | 位置をレジスタで渡す版（配列、借用） |
| `hchk rH` | 生きていれば Z フラグを立てる（`alive`、`Option` の読み出し） |
| `hbase rD, rH` | 検査して、オブジェクトのアドレスを返す（unsafe の実行時ライブラリ用） |

`Option<T>` の読み出しは `hchk` と分岐の2命令、`T` のフィールドの読み書きは1命令。表の場所は
入出力レジスタで渡し、カーネルが切り替えの時に書き換える（ページ表と同じ扱い）。直前に使った
行を1つ覚えておけば、同じオブジェクトを続けて触る時は表を読まずに済む。

命令を足さないと、1回の検査が15命令ほどになる（今の命令セットはシフトが1ビットずつで、
load にオフセットもないため）。このモデルは CPU の変更が前提。

### 7.3 実行時ライブラリ（unsafe）

- サイズ別のページから割り当てるアロケータ。
- 表の空き行のリスト、`new`・`delete`・`adopt`。
- 木を書き出す機能（デバッグ用）。型ごとの数、親ごとの子、根からの道。
- `hbase` で得たアドレスを使う間は、そのオブジェクトが消えないことを呼び出し側が保証する。

### 7.4 コンパイラ

- 足すもの: `object`、`new` / `new(親)` / `try_new`、`delete`、`adopt`、`alive`。ハンドルを
  通した読み書きを `ldh` / `sth` に。`Option<T>` の読み出しに `hchk`。ブロックの子の削除を、
  スコープの終わりの処理（`codegen_drop.c`）に足す。`delete` 後の使用の検査。
- そのまま使うもの: move の検査、借用の置き場所と衝突の検査（MLC-023、MLC-024）、`Drop`、
  範囲検査、ゼロ初期化、データだけの struct の自動コピー。
- 消すもの: `impl Copy`（規則 V2 の自動判定に置き換え）。
- 予約語: `object`・`adopt`・`alive` は今のコードで識別子として使われていない。`delete` は
  Files アプリのメソッド名に1つある（`void (Files *f) delete(i32 id)`）。

## 8. 見渡し

プロセスのメモリ全体が1本の木になる。DOM インスペクタと同じように眺められる。

```
root
├─ Window "Files"          128 B
│  ├─ Node #1 "a.txt"      128 B
│  └─ Node #2 ...
└─ Cache                    64 B
```

消し忘れは「長生きの親の下に、もう要らない子がたまっている」形で見える。

## 9. 書き味

```c
object Window { Text<32> title; Vec<Node> nodes; };
object Node   { String text; Option<Node> next; Window win; };

Window w = new(root) Window { title: "Files" };
Node n = new(w) Node { text: "a.txt", win: w };   // win は長生きなので `Window`
w.nodes.push(n);                                   // ハンドルを値の中に置くだけ
g_focus = Some(n);                                 // 消えうるので `Option<Node>`
n.text = "b.txt";                                  // 共有して書き換えられる

delete w;                                          // n も消える
case g_focus of { Some(x) -> x.text; None -> ""; } // None になっている
w.title;                                           // コンパイルエラー（delete 後の使用）
```

DOM のノードの作成（`dom.mln` の `create_node`）では、`heap.alloc` の失敗処理、`Node *` への
キャスト、約30行のゼロ埋めが1文になる。

```c
Node n = new(owner_root(g_current_owner)) Node { kind: kind, name: name };
```

アプリが終われば、その根を消すだけでノードがすべて消える。

## 10. 値だけのモデルとの比較

| | オブジェクトと世代（この文書） | 値だけ（`mylang-values.md`） |
| --- | --- | --- |
| 共有して書き換える | できる（object） | できない。つながりは `Pool` と `Handle` |
| つながりの書き方 | `n.next`、`n.win` | `case pool.get(h) of { ... }` |
| 解放 | 親か自分を消した時 | 最後の持ち主が手放した時（自動） |
| 消し忘れ | 漏れる（木を見れば分かる） | 起きない |
| 間違いが分かる時 | 触った時（None か trap） | 同じ（プールの `get` が None） |
| 実行時のコスト | 触るたびに1命令（CPU を変えた場合） | 共有値のコピーと解放で数命令、書く前のコピー |
| CPU の変更 | ほぼ必須 | 不要（あれば速い） |
| メモリの増分 | オブジェクト1つに 24 B | 共有値1つにヘッダ 8 B |
| 人が覚える言葉 | `object`、`new(親)`、`delete` | `new`、`Box`、`Pool`、`Handle` |
| 今の書き方との近さ | 近い（ポインタの付け替えがそのまま書ける） | 遠い（識別はプール経由） |
| 標準ライブラリ | `String`・`Vec` は今のまま | `String`・`Vec`・`Map` を共有値に作り直し、`Pool`・`Table` を追加 |

どちらも、安全の仕組みは「世代つきの番号で、消えたものを検出する」で同じ。違いは、それを
**言語が隠す**（`n.next` と書ける。そのぶん常に効くので CPU の支援が要る）か、
**ライブラリに出す**（`pool.get(h)` と書く。要る所だけで済む）か。

### 10.1 最初の草案から変えた所

`mylang-tree-generation-memory.md` から次を変えた。

- **weak と own をなくした。** 人は `Option<T>` か `T` かだけを決める（規則 O6）。
- **値はまるごとコピーしない。** 値は今のまま（データはコピー、`drop` を持つ型は move）。
  共有が要るものは object にする。`String`・`Vec` を作り直さなくてよい。
- **境界（スタックが空になった時）をなくした。** 世代で検出するので、メモリはすぐ再利用
  できる。
- **登録してゼロにする仕組みを採らなかった。** 読む時を無料にできるが、ハンドルを置く場所が
  3語になり、置くたび・上書きのたびにリストの付け替え（10〜20命令）が要る。つながりは
  「1回置いて何回も読む」ものなので、読む時に1命令払うほうが安い。

## 11. 代償

- **CPU の変更がほぼ必須。** §7.2 の命令がないと、触るたびに15命令ほどかかる。
- **消し忘れは漏れる。** 親を長生きさせすぎた場合など。安全は壊れない。木を見れば分かる。
- **`T` と書いたフィールドが生きていることを、コンパイル時には保証できない。** 消えた相手に
  触れば trap で止まる。
- **オブジェクト1つに 24 バイト増える。** DOM のノード（104 B）なら約 23%。
- **`delete` を人が書く場面が残る。** まれだが、ゼロではない。

## 12. 未決事項

- 表を使うか、オブジェクトの頭に世代を置くか（頭に置くと 16 B 減るが、世代が 7〜8 ビット
  になり、同じ大きさの種類でしか再利用できない）。
- `Option<T>` を1語に収める表現（None = 0）と、`case` の生成コード。
- 配列・コンテナの中の死んだハンドルの掃除（誰がいつ行うか）。
- `adopt` の綴りと、ブロックの子を return した時の扱い（コンパイラが警告する案）。
- カーネルでブロックするスレッドが、待つ間ハンドルを持てるか（木を変える操作との競合）。
- 採用したら、MLC-025・MLC-026 をこの文書に合わせて書き直す。

## 13. 試作の計画

1. エミュレータとアセンブラに、オブジェクト表と §7.2 の命令、trap `0x1BAD02`〜`0x1BAD04` を
   足す。
2. 実行時ライブラリ（unsafe な MyLang）に、表、`new`・`delete`・`adopt` を書く。
3. コンパイラに最小限を足す。`object`、`new(親)`、`delete`、`alive`、フィールドの読み書き、
   `Option<T>` の読み出し。
4. 止まるまで動く比較用のプログラムで、木を作る・たどる・消す処理の命令数を比べる。今の
   生ポインタ、値だけのモデル、このモデルの3つ。
5. DOM の一部を書き直して、書き味を見る。
