# 実行の文脈（地図の点線の枠）

## ctx.user  アプリのプロセス（ユーザ空間）
実行の文脈
走る：アプリのスレッド

アプリと、それがリンクした SDK と MyStdLib。OS の中には [[kernel.os-call]] でしか入れない。

## ctx.syscall  OS_CALL の中
実行の文脈
走る：アプリのスレッド
カーネルの中：はい

呼んだプロセスの代わりに、カーネルの権限で走る。ユーザメモリの読み書きは、ここでコピーして済ませる（[[os.gateway]]）。

## ctx.service  service task
実行の文脈
走る：service task（OS のスレッド）
カーネルの中：はい

MyOS 自身のスレッド。[[os.request-ring]] から要求を取り出して答える。[[os.dom]] に触るのはこのスレッドだけ。

## ctx.irq  割り込みの中
実行の文脈
走る：割り込み
カーネルの中：はい

タイマーなどの割り込みで、走っていたものを止めて入る。スレッドの切り替えはここで起きる。
