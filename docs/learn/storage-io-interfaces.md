# ストレージデバイスの I/O インターフェース設計

CPU からストレージ（SSD/Flash/EEPROM）にアクセスする方法はいくつかある。
それぞれハードウェアの複雑さ、ソフトウェアの手間、速度のトレードオフが異なる。

---

## 前提知識

### メモリマップド I/O とは

CPU のメモリアドレス空間の一部を、RAM ではなくデバイスの「レジスタ」に割り当てる方式。
CPU から見ると普通の `load` / `store` 命令でデバイスと通信できる。

```
アドレス空間:
  0x00000000 - 0x1FFFFFFF : RAM
  0x24000000 - 0x240000FF : I/O レジスタ  ← ここにデバイスが住む
```

例えば、シリアルポートの送信は：
```
store 0x24000000, 'H'   ; 0x24000000 に書き込む = シリアルで 'H' を送信
```

### バスマスタリング / DMA とは

通常はCPUだけがバス（アドレス線+データ線）を使ってRAMにアクセスする。
**DMA（Direct Memory Access）** では、デバイスがCPUに代わってバスを乗っ取り、
RAM に直接読み書きする。CPUは転送中は何もしなくてよいが、ハードウェアが複雑になる。

```
DMA方式:
  CPU → デバイスに「ブロック5をRAMの0x1000に読め」と指示
  デバイス → バスを占有してRAMに256バイト書き込む
  デバイス → 完了を通知
```

離散ロジック（4000シリーズICなど）で DMA を作るのは非常に難しい。
バス調停（アービトレーション）、タイミング制御、アドレスカウンタなどが必要。

## 方式の比較

### 方式1: バイト単位 I/O（推奨 ⭐）

レジスタ3本だけのシンプルな設計。

```
レジスタ:
  BLOCK  (W)  : どのブロックにアクセスするか (0〜255)
  OFFSET (W)  : ブロック内のバイト位置 (0〜255)。DATAアクセスで自動+1
  DATA   (R/W): 1バイトずつ読み書き

読み出し手順:
  store BLOCK, 5       ; ブロック5を選択
  store OFFSET, 0      ; 先頭から読む
  load  R0, DATA       ; 1バイト読む (offset → 0→1)
  load  R1, DATA       ; 次の1バイト読む (offset → 1→2)
  ...                  ; 256回繰り返す

書き込み手順:
  store BLOCK, 5       ; ブロック5を選択
  store OFFSET, 0      ; 先頭から書く
  store DATA, 0x41     ; 1バイト書く ('A')
  store DATA, 0x42     ; 次の1バイト書く ('B')
  ...
  store CMD, COMMIT    ; 変更をストレージに確定
```

**ハードウェア構成:**

```
  CPU バス
    │
    ├─ アドレスデコーダ ─── BLOCK レジスタ (8bit)
    │                   ├── OFFSET カウンタ (8bit, +1機能付き)
    │                   └── DATA 線
    │
    ├─ {BLOCK, OFFSET} ──→ ストレージチップのアドレス入力
    └─ DATA            ──→ ストレージチップのデータ入力
```

必要な IC:
- アドレスデコーダ: 74HC138 等 × 1
- BLOCK レジスタ: 74HC574 (8bit ラッチ) × 1
- OFFSET カウンタ: 74HC161 (4bit カウンタ) × 2 (カスケードで8bit)
- ストレージ: EEPROM (28C256 = 32KB) or SRAM + バッテリバックアップ

**メリット:**
- ハードウェアが最もシンプル（IC 5〜6個）
- DMA不要、バス調停不要
- CPUがストレージ速度を気にしなくてよい（同期アクセス）

**デメリット:**
- 256バイト転送に256回のload/store命令が必要（遅い）
- CPUが転送中ずっとビジーになる

**向いている場面:**
- 離散ロジック/IC で作る場合（まさにこのプロジェクト！）
- 速度より設計のシンプルさを優先する場合

---

### 方式2: ページウィンドウ方式

ストレージの1ブロック分（256バイト）を、I/O空間に直接マッピングする。

```
レジスタ:
  PAGE_SELECT (W) : どのブロックを窓に映すか
  WINDOW[0..255]  : 選択中ブロックの256バイトがここに見える

使い方:
  store PAGE_SELECT, 5   ; ブロック5を窓に映す
  load  R0, WINDOW+0     ; ブロック5のbyte0を読む
  load  R1, WINDOW+1     ; ブロック5のbyte1を読む
  store WINDOW+10, 0x41  ; ブロック5のbyte10に書く
```

**メリット:**
- ランダムアクセスが簡単（任意のオフセットに直接アクセス）
- OFFSETレジスタが不要

**デメリット:**
- I/O空間を256バイト占有してしまう（このアーキテクチャのI/O空間は全部で256B）
- 他のデバイス（シリアル、キーボード、ディスプレイ）と共存できない
- ハードウェア的にもアドレスデコードが複雑になる

**向いている場面:**
- I/O空間に余裕がある場合
- ランダムアクセスが多い場合

**このアーキテクチャでは不適切:** I/O空間が256Bしかないため、SSD単独で使い切ってしまう。

---

### 方式3: コマンド + FIFO方式

ブロック単位の転送をFIFOバッファ経由で行う。

```
レジスタ:
  CMD   (W)  : READ=1, WRITE=2
  BLOCK (W)  : ブロック番号
  DATA  (R/W): FIFOの入出口
  STATUS (R) : FIFO状態

読み出し:
  store BLOCK, 5          ; ブロック5
  store CMD, READ         ; 読み出しコマンド → 内部FIFOに256バイトロード
  load  R0, DATA          ; FIFOから1バイト取り出す
  load  R1, DATA          ; 次の1バイト
  ...                     ; 256回

書き込み:
  store BLOCK, 5          ; ブロック5
  store CMD, WRITE_BEGIN  ; 書き込み開始
  store DATA, 0x41        ; FIFOに1バイト入れる
  store DATA, 0x42        ; ...
  ...                     ; 256回入れる
  store CMD, WRITE_COMMIT ; FIFOの内容をストレージに書き込み
```

**メリット:**
- ブロック全体をアトミックに操作（途中で電源が切れてもデータ破壊しにくい）
- シーケンシャルアクセスに最適

**デメリット:**
- 256バイトのFIFOバッファが必要（SRAM IC追加）
- FIFO制御ロジック（書き込みポインタ、読み出しポインタ）が必要
- ランダムアクセスができない（先頭から順番に読むしかない）

**向いている場面:**
- データ完全性が重要な場合
- ストレージが遅い場合（FIFOでバースト転送）

---

### 方式4: DMA方式

デバイスがRAMに直接読み書きする。

```
レジスタ:
  CMD    (W) : READ=1, WRITE=2
  BLOCK  (W) : ブロック番号
  ADDR   (W) : RAM上の転送先アドレス
  STATUS (R) : 転送状態

使い方:
  store BLOCK, 5           ; ブロック5
  store ADDR, 0x1000       ; RAMの0x1000に転送
  store CMD, READ          ; 転送開始
  ; CPUは他の仕事ができる
  load  R0, STATUS         ; 完了を確認
```

**メリット:**
- CPU負荷が最小（1コマンドで256バイト転送完了）
- カーネルのコードがシンプル

**デメリット:**
- バス調停回路が必須（デバイスとCPUがバスを共有するため）
- デバイス側にアドレスカウンタ＋バス制御ロジックが必要
- 離散ロジックでの実装は非常に複雑（IC 20個以上）
- タイミング設計が難しい

**向いている場面:**
- 高速な転送が必要な場合
- チップセットやFPGAで実装する場合

**このアーキテクチャでは過剰:** 離散CMOSロジック向けには複雑すぎる。

## この MyComputer アーキテクチャへの推奨

### ⭐ 方式1（バイト単位 I/O）を推奨

理由:
1. **ハードウェアが最もシンプル** — カウンタ+ラッチ+デコーダだけ
2. **I/O空間の消費が最小** — レジスタ4本（16バイト）だけ
3. **DMA/バス調停が不要** — 離散ロジックで実装可能
4. **実績のあるパターン** — 初期のPCのフロッピーコントローラや
   組み込み系のEEPROMインターフェースと同じ発想
5. **十分な速度** — 1MHz動作で256バイト転送に約1000命令（〜1ms）。
   ファイル操作の頻度を考えれば全く問題ない

### 推奨レジスタマップ

| アドレス | 名前 | R/W | 説明 |
|----------|------|-----|------|
| `0x24000010` | `SSD_BLOCK` | R/W | ブロック番号 (0-255) |
| `0x24000014` | `SSD_OFFSET` | R/W | ブロック内オフセット (0-255)。DATA アクセスで自動+1 |
| `0x24000018` | `SSD_DATA` | R/W | 1バイトデータの読み書き |
| `0x2400001C` | `SSD_CMD` | R/W | コマンド/ステータス。COMMIT(1)=変更をストレージに書き込み、読み出し時: 0=正常, 0xFF=エラー |

### カーネル側の使い方（ブロック読み出し）

```
// ブロック5をRAMバッファに読み出す
mem.write_word(SSD_BLOCK, 5);
mem.write_word(SSD_OFFSET, 0);
i32 i = 0;
while (i < 256) {
    i32 byte_val = mem.read_word(SSD_DATA);  // 1バイト読む, offset自動+1
    char *p = (char *)(buf + i);
    *p = (char)byte_val;
    i = i + 1;
}
```
